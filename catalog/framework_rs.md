# Rust Framework

This file is the catalog of the Rust library in `framework_rs/`.

Each row has the entry path, a short description, and the open behaviour. Update that row in the same change when you make a new decision, the entry moves, or you add or remove a feature. When a code change would change the open behaviour and you did not make that decision, stop and ask. Leave the decision as it is.

| Path | Description | Decision |
| --- | --- | --- |
| `framework_rs/src/logging/` | Request and event logging, and the browser log route `POST /log` | The project gives the log server endpoint and the POST API key. The logger locks its buffer with `framework_rs/src/mutex.rs`. `trace_event` writes an empty context when the context does not encode. The library does not read those settings from the environment. An authorized POST is trusted, so the log server stores the `context` and the `extra` that the project sets. A flush stops after three failed batches, so a down log server does not keep the process open. `with_log` sets the latency after it builds the event, so the builder cannot replace the latency. A log value is a bool, a number, or a string. Deserialize rejects null, an array, and an object. The default mask patterns hide a credential in a field name and in a name-value pair, because the access log records the query and the JSON body. Client log text replaces a control character with a space and does not keep text above the limit. A client key is camelCase. The stored key is snake_case. A rejected client log is a bad request exception response. A refused ship is a bad gateway exception response. |
| `framework_rs/src/monitor/` | CPU and disk monitors | The module compiles only with the Cargo feature `monitor`, and only on Linux. A monitor makes one `LogEvent` when the usage rises to a threshold, and it gives the event to a sink that the caller supplies. The alert arms again when the usage falls below the threshold. Disk usage follows `df`. The blocks that root cannot use are not free, and the blocks that only root can use are not counted. A threshold of 0, less than 0, more than 100, or not a number, or a zero interval, returns no monitor and writes a warning. That result is not an exception. The warning puts the threshold and the interval in the log fields. The first failed read writes a log record and stops the task. A later failed CPU read writes one error and the loop continues. A later failed disk read skips that sample and writes no log record. |
| `framework_rs/src/gcp/storage/` | Google Cloud Storage client | The client compiles only with the Cargo feature `gcs`. The official crates own authentication, token refresh, and retries. The project gives the signer email. With no signer email, the signer is the account of the credentials, and that account must be a service account or the metadata server. A copy that needs more than 10000 rewrite calls is a fault. `merge_object_metadata` replaces a key of the same name and keeps the other keys. A move deletes the new object only when the source object still exists. A failed delete does not prove that the source still exists. A missing object is a normal result and writes no log record. An object name longer than 1024 bytes is refused, because GCS refuses a longer name. The message for a failed open, a failed metadata read, or a path that is not a file contains no file path. |
| `framework_rs/src/http/` | HTTP boundary error, request header helpers, safety and security middleware, the version route, the health route, and the SPA route | A handler can return `Result<T, Exception>`, and the library turns that exception into the HTTP response. The project attaches the middleware. The library serves the version route, the health route, and the SPA route. The SPA route returns the HTTP response from the handler. A missing dist and an unreadable file are logged with `NOT_FOUND`. The response is an internal error. The access log and the rate limiter lock with `framework_rs/src/mutex.rs`. The response status comes from the code of the top exception. A code that is not a client status becomes an internal error, and the client does not receive the wrapped error. The library keeps the exception on the response for code in this process. The HTTP client does not receive that value. The access log writes `ip`, `user_agent`, and `request_url` after the handler fields, so a handler cannot replace those keys. Same-origin uses `Sec-Fetch-Site` when that header is present. When it is absent, the check compares `Origin` with `Host`, because a browser that does not send `Sec-Fetch-Site` still sends `Origin` on a POST. The cookie reader reads every `Cookie` field, because an HTTP/2 client can send each cookie in its own field. A bearer key compare uses the SHA-256 hashes, because slices of different lengths compare in less time. All addresses in one IPv6 /64 share one rate-limit bucket. A full rate-limit map drops a batch of the least recently used buckets at one time, so a full scan is rare. `on_reject` stores one function. The function accepts the request and returns a future. The function owns the request. The request is `Send`. The future can use the request after it waits. The function is `Send` and `Sync`, so two calls can run at the same time. The middleware waits for that future. Then it returns the unauthorized response. The future does not change that response. |
| `framework_rs/src/token.rs` | RFC 9110 `token68` check | `is_token68` accepts a text only when that text is a `token68`. A `token68` is one or more of a letter, a digit, `-`, `.`, `_`, `~`, `+`, or `/`, then any number of `=`. A project can use the check to reject an API key at startup. |
| `framework_rs/src/redis.rs` | Redis connection helper | The module compiles only with the Cargo feature `redis`. `connect` returns a connection manager only when Redis replies `PONG` to `PING`. The error does not contain the Redis URL. A `rediss://` URL connects with TLS. The connection fails fast when Redis is down. It does not retry for many seconds. |
| `framework_rs/src/auth/` | Cookie sessions and password hashes | The module compiles only with the Cargo feature `auth`, and that feature enables `redis`. A password has 8 to 256 bytes and contains an English letter and a digit. `verify_password` returns an exception when the password fails those rules or the hash is not a PHC string. A password that does not match returns false. The library does not store users. A session token is 64 lowercase hex characters. Any other value does not call Redis. A Redis key holds the hash of the token, so a copy of Redis does not give a working token. The subject set key is a hash of the subject, so the subject cannot change that key. `remove` deletes the session key. That key can stay in the subject set until `create` or `remove_subject` clears it. A trim removes the keys of expired sessions first, then ends the least recently used sessions, and it does not end the new session. The session TTL is at most 400 days, because a browser caps a cookie lifetime at 400 days. The session cookie and the clear cookie use the same attributes, `HttpOnly`, `Secure`, `SameSite=Lax`, and `Path=/`, because a browser removes the cookie only when the attributes match. A cookie name is one or more visible ASCII characters and has no separator. |
| `framework_rs/src/exception.rs` | Shared error type `Exception` | `Exception` is the one error type of the library. Build one only with the `exception!` macro. The message and `Debug` do not show the source, because the source can hold a secret. `location` is the file and the line of the `exception!` call. `trace` starts at this exception and follows each source that is an `Exception`. |
| `framework_rs/src/shutdown.rs` | Shutdown signal `ShutdownReceiver` | All clones share one state. `SIGINT`, `SIGTERM`, or `trigger` sets that state. The state stays triggered. A listener that fails to install does not set the state. `wait` returns a `'static` future that owns its receiver, so the caller does not borrow `ShutdownReceiver`. |
| `framework_rs/src/mutex.rs` | Standard mutex lock | `lock` returns the guard. A poisoned mutex calls `clear_poison` and the caller continues with the guard. |
| `framework_rs/src/env.rs` | Environment variable read helpers | `required` and `optional` read only the environment variable of the name that the caller gives. They do not read Secret Manager. The error holds the name and does not hold the value, because the value can be a secret. |
| `framework_rs/src/gcp/` | Shared Google Cloud code and Secret Manager access | The module compiles only with the Cargo feature `gcp`. The official crates read Application Default Credentials. The project chooses the fallback from Secret Manager to an environment variable. The library reads `GOOGLE_CLOUD_PROJECT`, which is a Google Cloud standard variable and not an app setting, and it reads the project id from the metadata server. No variable and no metadata answer means that the process has no project. `SecretManager::shared` returns no client in that case. `access_latest` returns no value when the secret or its latest version does not exist. An error does not hold the secret value or a parser error that can quote it. A control client error can be a gRPC status in place of an HTTP status. Both forms use the same error codes. |
| `framework_rs/src/time/` | Hong Kong time `hkt_now` and `hkt_today`, and `Quarter` | The helpers use Hong Kong time only. Hong Kong time is the fixed offset UTC+08:00, and it has no daylight saving time. `new` returns an exception when the quarter number is outside 1 to 4. `of` returns the quarter of a day. `first_day` and `last_day` return text of the year, the month, and the day, because the stored day is that text. |
