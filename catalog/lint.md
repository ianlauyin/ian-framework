# Lint

This file is the catalog of the linter in `lint/`.

Each row has the entry path, a short description, and the open behaviour. Update that row in the same change when you make a new decision, the entry moves, or you add or remove a feature. When a code change would change the open behaviour and you did not make that decision, stop and ask. Leave the decision as it is.

| Path | Description | Decision |
| --- | --- | --- |
| `lint/Cargo.toml` | The crate `ian-lint` | The package name is `ian-lint`. The program name is `ian-lint`. |
| `lint/src/config.rs` | The configuration file | The file name is `ian-linter.config`. The file is in the root folder. The file is JSON. The fields are `ruleset`, `fe.path`, and `be.path`. `ruleset` is `framework`. `fe.path` is the list of frontend src folders. `be.path` is the list of backend src folders. A path in a list is relative to the root folder. The library joins that path to the root folder. A list can be empty. An empty path, an absolute path, or a path with `..` is an error. A ruleset other than `framework` is an error. An unknown field is an error. |
| `lint/src/lib.rs` | Lint run for one root folder | The caller gives the root folder. The library reads `ian-linter.config` in that folder. `check_files` sends a `.ts` or `.tsx` file, or a style file, under a frontend src folder to the frontend rules, and a `.rs` file under a backend src folder to the Rust rules. `check_folders` sends a folder under a frontend src folder to the frontend folder rules, and a folder under a backend src folder to the Rust folder rules. A folder that is under both src lists goes to both folder rules. A configuration error returns before the walk. The report holds that failure and has no walk error. A walk error is a failure when the configuration file loads. A failure holds the reason, and a failure is not a lint error. The diagnostics are in the order of path, then line. |
| `lint/src/main.rs` | The `ian-lint` program | The argument is the root folder. The default root is the current folder. The program prints the diagnostics on stdout. It prints a tool failure on stderr. It exits with code 1 when there is a diagnostic, with code 2 when there is a tool failure, and with code 0 when there is none. `NO_COLOR` turns the color off when the variable is set and not empty. `FORCE_COLOR` turns the color on when the variable is set, not empty, and not `0`. With neither variable, the color is on when the stream is a terminal. A name in backticks is yellow. A backtick with no pair stays as it is. |
| `lint/src/diagnostic.rs` | One error and the ignore comment | A diagnostic has a fix. The problem says what is wrong. The fix says what to change. The text shows `ian-lint` before the rule id. The comment `ian-lint-ignore` with a rule id stops that rule on the same line and on the next line. The comment can give a reason after the rule id. Line and column are 1-based. A diagnostic for a whole file uses line 1 and column 1. A position can come from a byte offset in the source. |
| `lint/src/files.rs` | The file tree and the file kinds | The walk obeys `.gitignore`, also when the root is not in a git repository. The walk records each file and each folder that it can read. The second result is the errors of the walk. A folder that the walk cannot read is not in the set. The caller gives the src folders. A `.ts` or `.tsx` file under one src folder, or a style file, is a frontend source file. A `.d.ts` file is not a frontend source file. A `.css` file under one src folder is a style file. A `.rs` file under one src folder is a Rust source file. |
| `lint/src/rule/mod.rs` | The two rule sets | A TypeScript rule is a file in `lint/src/rule/fe/ts/`. A CSS rule is a file in `lint/src/rule/fe/css/`. A frontend folder rule is a file in `lint/src/rule/fe/folder/`. A Rust rule is a file in `lint/src/rule/rs/`. A Rust folder rule is a file in `lint/src/rule/rs/folder/`. |
| `lint/src/rule/fe/mod.rs` | The frontend rules | `check` is the call from `check_files` for a frontend source file or a style file. It sends a `.css` file to the `css` module and any other file to the `ts` module. `check_folder` is the call from `check_folders` for a folder under a frontend src folder. It calls the `folder` module. |
| `lint/src/rule/fe/css/mod.rs` | The CSS rules | `check` is the call from `lint/src/rule/fe/mod.rs` for a `.css` file. The module has no rules. |
| `lint/src/rule/fe/folder/mod.rs` | The frontend folder rules | `check` is the call from `check_folder` in `lint/src/rule/fe/mod.rs`. The module has no rules. |
| `lint/src/rule/fe/ts/mod.rs` | The TypeScript rules | `check` is the call from `lint/src/rule/fe/mod.rs` for a file that is not a `.css` file. `check_files` sends a `.ts` or `.tsx` file. `check` calls `lint/src/rule/fe/ts/no_restricted_imports.rs`. |
| `lint/src/rule/fe/ts/no_restricted_imports.rs` | The import path rule | The rule parses the file with oxc. A file extension that oxc does not accept has no diagnostic from this rule. An import specifier is an error when one path segment is `node_modules` and one segment follows it. The specifier comes from a static `import`, a static `export`, an `import()` call with a string argument, or an `import` binding that uses `require`. A `require()` call is not an error. A template `import()` is not an error. A string that is not a specifier is not an error. A member named `import` is not an error. Text in JSX is not an error. The problem names the specifier. The fix says to import the package by its name. The comment `ian-lint-ignore` with `no-restricted-imports` stops the rule. |
| `lint/src/rule/rs/mod.rs` | The Rust rules | `check` is the call from `check_files` for a Rust source file. `check` calls `lint/src/rule/rs/private_static.rs`. `check_folder` is the call from `check_folders` for a folder under a backend src folder. It calls the `folder` module. |
| `lint/src/rule/rs/private_static.rs` | A private static | A `static` item that has visibility is an error. A `static` in an inline module and a `static` in an `extern` block follow the same rule. A private `static` is not an error. A file that is not valid Rust gives no error from this rule. The problem names the static. The fix says to remove the visibility. The comment `ian-lint-ignore` with `private-static` stops the rule. |
| `lint/src/rule/rs/folder/mod.rs` | The Rust folder rules | `check` is the call from `check_folder` in `lint/src/rule/rs/mod.rs`. The module has no rules. |
