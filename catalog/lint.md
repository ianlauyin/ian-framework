# Lint

This file is the catalog of the linter in `lint/`.

- The decision records a behaviour that the code does not show. 
- Update that row in the same change when you make a new decision, the entry moves, or you add or remove a feature. 
- When a code change would change the decision and you did not make that decision, stop and ask. Leave the decision as it is.

| Path | Description | Decision |
| --- | --- | --- |
| `lint/Cargo.toml` | The crate `ian-lint` | |
| `lint/src/lib.rs` | The exported check, the report, and the failure | `args`, `config`, `file`, `files`, and `rule` are public. |
| `lint/tests/` | The tests | A test is in `check`, `css`, `folder`, `rs`, or `ts`. |
| `lint/src/config.rs` | The configuration file and the side | `ruleset` is `framework` or `project`. A side checks the frontend, Rust, or both. A path is a package folder. The key of the frontend package paths is `fe`. The key of the Rust package paths is `be`. A package path that is not a folder is a failure. |
| `lint/src/check.rs` | The check of one root folder | The linter checks the files in `src` and in `tests` of each package. It does not check the other files in a package. A folder rule starts only at a folder in `src`. A folder rule for the two sides runs with each side argument. It gets the src folders of the frontend and of Rust. A file that the linter cannot read is a failure. A TypeScript or Rust file that does not parse is a failure. The rules do not check that file. |
| `lint/src/main.rs` | The `ian-lint` program | |
| `lint/src/args.rs` | The arguments of the `ian-lint` program | `fe` checks only the frontend. `be` checks only Rust. No side argument checks both. The other argument is the root. The root is `.` when it is omitted. The arguments can be in either order. Two roots, or two sides, stops the run. `-h` or `--help` gives the usage. A different argument that starts with `-` stops the run. |
| `lint/src/files.rs` | The file tree and the file kinds | The walk skips each `node_modules` folder, also when no ignore file names it. |
| `lint/src/ruleset.rs` | The rules in each ruleset | `FRAMEWORK` and `PROJECT` each hold `css`, `ts`, `rs`, and `folder`. The `framework` ruleset runs `FRAMEWORK`. The `project` ruleset runs `PROJECT`. |
| `lint/src/file/mod.rs` | The data for one source file | |
| `lint/src/file/place.rs` | The src-relative place of a file | A file in `tests` adjacent to the src folder has a place in the `tests` folder. The Rust rules, the TypeScript rules, and the CSS rules use it. |
| `lint/src/file/css/mod.rs` | The CSS parser | |
| `lint/src/file/css/source.rs` | The CSS source and statements for one file | |
| `lint/src/file/css/parse.rs` | The CSS statements | lightningcss gives the start of each rule that it knows. The byte scanner gives each span, each declaration, and each comment. The byte scanner also parses each rule that lightningcss drops. A rule from lightningcss that is outside its block, or that overlaps the previous item, is not used. When lightningcss fails, the byte scanner parses the full file. A stray `}` is skipped. A `{` or a `}` in parentheses or brackets does not open or close a block. A stray `)` or `]` does not change the depth. A statement that starts with `@` is an at-rule. A statement that starts with `--` and has a block is a declaration. A statement ends after `;`, before `}`, or at the end of the file. An unclosed block ends at the end of the file. |
| `lint/src/file/css/position.rs` | The byte offset of a lightningcss location | A line number starts at 0. A column starts at 1 and counts UTF-16 units. `\r\n`, `\r`, `\n`, and a form feed each end a line. |
| `lint/src/file/css/scan.rs` | The byte scanner that finds the end of a statement or a block | `/*` in a `url(...)` that has no quote does not start a comment. |
| `lint/src/file/css/selector.rs` | The selectors in a selector list and the class names in a selector | A comma in parentheses, in brackets, in a string, or in a comment does not divide the list. A `.` in brackets, in a string, or in a comment does not start a class name. A `.` before a digit does not start a class name. |
| `lint/src/file/css/sheet.rs` | The items for the rules that lightningcss gives | |
| `lint/src/file/ts/mod.rs` | The TypeScript parser | |
| `lint/src/file/ts/declaration.rs` | The named imports of one path, the type of a constant, and the base class of a class | Only an `import` at the top level with braces is read. A constant is a `const` at the top level, also when it is exported. The type of a constant that is an arrow function is the return type of the function. The type of each other constant is its type annotation. Only a plain type name is a type. |
| `lint/src/file/ts/source.rs` | The TypeScript source and syntax tree for one file | |
| `lint/src/file/rs/mod.rs` | The Rust parser | |
| `lint/src/file/rs/item.rs` | The type name and the visibility of a Rust item | |
| `lint/src/file/rs/macro_body.rs` | The code in a macro call | The arguments are read as expressions with commas between them. When that fails, the arguments are read as statements. When the two fail, the code in the macro call is not checked. The rules `config-import`, `env-name`, `exception-code`, `exception-new`, `mutex-lock`, `no-panic`, `ops-import`, `sqlx-import`, `std-env`, `super-path`, and `test-crate-path` check the code in a macro call. |
| `lint/src/file/rs/source.rs` | The Rust source and syntax tree for one file | |
| `lint/src/rule/mod.rs` | The rule modules | The `mod.rs` in `lint/src/rule/css/`, `lint/src/rule/ts/`, `lint/src/rule/rs/`, and `lint/src/rule/folder/` holds the module declarations and the rule type. Each other `mod.rs` holds only module declarations. The rules that check one file are in `lint/src/rule/css/`, `lint/src/rule/ts/`, and `lint/src/rule/rs/`. The rules that check one folder are in `lint/src/rule/folder/`. CSS has no folder rule. The CSS file data is in `lint/src/file/css/`. The TypeScript file data is in `lint/src/file/ts/`. The Rust file data is in `lint/src/file/rs/`. There is no `support` folder. |
| `lint/src/rule/diagnostic.rs` | One error | |
| `lint/src/rule/report.rs` | The diagnostics of one rule in one file | |
| `lint/src/rule/folder/mod.rs` | The folder rules and the folder rule type | |
| `lint/src/rule/folder/fe_ajax_tree.rs` | The ajax tree matches the router tree | Only the `project` ruleset runs it. It is a rule for the two sides. The ajax tree is `util/ajax/api` directly in a src folder. The router tree is `router/api` directly in a src folder. Each `.ts` file in the ajax tree has a `.rs` file with the same path in a router tree. `mod.rs` is not a handler file. A handler file does not need an ajax file. A file below `util/ajax` that is not in the ajax tree is not checked. When no src folder has a router tree, the rule does not check. |
| `lint/src/rule/folder/fe_component_folder.rs` | Each component folder has an `index.tsx` | Only the `project` ruleset runs it. A component folder is a folder directly in `component` in the src folder. A folder deeper in a component folder is not checked. The rule name is `component-folder`, the same as the TypeScript rule. |
| `lint/src/rule/folder/fe_index_file.rs` | Each source folder has an `index.ts` or an `index.tsx` | |
| `lint/src/rule/folder/fe_module_folder.rs` | The `module` folder has an `index.ts`, and each module folder has an `index.ts` and a `type.ts` | Only the `project` ruleset runs it. A module folder is a folder directly in `module` in the src folder. When the `module` folder exists, it must have `index.ts`. A TypeScript file directly in `module`, other than `index.ts`, is an error. A folder deeper in a module folder is not checked. The rule name is `module-shape`, the same as the TypeScript rule. |
| `lint/src/rule/folder/fe_root_reexport.rs` | The root index re-exports each feature | A nested index can leave out an export for a sibling file. |
| `lint/src/rule/folder/fe_test_tree.rs` | The test tree matches the source tree | A source file does not need a test file. |
| `lint/src/rule/folder/rs_router_folder.rs` | The folders of the API router | Only the `project` ruleset runs it. The API router is `router/api` directly in the src folder. A `router` folder at a different place is not checked. Only `mod.rs` and folders are directly in the API router. A folder with the name `public` or `protected` at any depth below the API router is an error. A feature folder can contain folders. The files in a feature folder are not checked. |
| `lint/src/rule/folder/rs_test_tree.rs` | The test tree matches the crate | A source file does not need a test file. The test folder is `tests` in the src folder or `tests` adjacent to the src folder. The two are checked. In `tests` in the src folder, the test root is `mod.rs`. In `tests` adjacent to the src folder, each file directly in `tests` is a test root, and `tests` does not need a `mod.rs`. A test root does not need a source file. A test root follows `lib.rs`. When `lib.rs` is absent, it follows `main.rs`. In `tests` adjacent to the src folder, a `mod.rs` can follow the source file that has the name of its folder. |
| `lint/src/rule/css/mod.rs` | The CSS rules and the CSS rule type | An id selector and descending specificity are not checked. Only `css-class-prefix` checks a class name. |
| `lint/src/rule/css/class_prefix.rs` | The class names in `component` and in `page` | Only the `project` ruleset runs it. `component` and `page` are directly in the src folder. Each CSS file in the two folders is checked. In a component, the name is the folder directly in `component`, in kebab-case. The root selector of a file directly in that folder is `.g-{name}`. The root selector of a deeper file is one class that starts with `g-{name}-`. Each other class starts with `g-`. In a page, a page folder is a folder below `page` with a name that starts with a lowercase letter. A page name is the name of a page folder, or the part of that name after a `-`. The root selector is the id `#{page}-page`, or one class that starts with `{page}-page-`. The root selector `.{page}-page` is an error. Each other class starts with the `{page}-page-` of the root selector or with `g-`. A file below `page` that has no page folder is not checked. An id in a nested selector is not checked. The rules in `@media`, `@supports`, `@container`, and `@layer` are checked. The rules in each other at-rule are not checked. When a root selector is an error, the rules in its block are not checked. |
| `lint/src/rule/css/empty_line_before.rs` | An empty line before a rule | The first node of a file is not checked. The first child of a block has no empty line before it. A rule after a single-line comment has no empty line before it. |
| `lint/src/rule/css/selector_nested_pattern.rs` | A nested selector | Each selector in a list is checked on its own. A rule in an at-rule is not checked. |
| `lint/src/rule/css/single_root.rs` | One root selector in an `index.css` | Only the `project` ruleset runs it. The `index.css` directly in the src folder is not checked. A file with a different name is not checked. Each selector in a list is one root selector. A rule in an at-rule is not a root selector. |
| `lint/src/rule/run.rs` | The run of the frontend rules on one file | A TypeScript file in `tests` adjacent to the src folder is a test file. The rules `ajax-name`, `capture-action-name`, `component-folder`, `declaration-order`, `import-alias`, `module-import`, `module-registration`, `module-shape`, `no-arrow-method`, `no-console`, `page-context`, `page-import`, `private-method-order`, and `test-path` do not check a test file. |

A file with no exported function declaration is an error. A type is an interface or a type alias with a name that ends with `Request` or `Response`. Only a type and a different type can be between a type and the function after it. A declaration with a different name is not checked. |
| `lint/src/rule/ts/ajax_no_extends.rs` | No `extends` in an ajax file | Only the `project` ruleset runs it. An ajax file is a file below `util/ajax` in the src folder. Each class with `extends` and each interface with `extends` is an error. A test file is checked. |
| `lint/src/rule/ts/capture_action_name.rs` | The action name of `Logger.capture` in a page context | Only the `project` ruleset runs it. It checks a class that extends `PageContext` by a plain name. The page name is the class name without the `Page` at the end, with a lowercase first letter. The folder of the file does not give the page name. The method is the class method that contains the call. A first argument that is not a string literal is an error. A call outside a method of such a class is not checked. |
| `lint/src/rule/ts/component_folder.rs` | The export and the props type of a component | Only the `project` ruleset runs it. It checks each `index.tsx` below `component` in the src folder. | `lint/src/rule/ts/declaration_order.rs` | The declaration order | A private `let` is in the same group as a constant. A statement that has no group, such as a call, a class, or an enum, is allowed at any place in each file and does not change the order. |

An alias path in a file in `util` or `i18n` to its own folder is not an error. A relative path that goes out of the src folder is not checked. An `import`, a re-export with `from`, and an `import()` with a string literal are each checked. |

The order in one group is not checked. An empty line between the groups is not checked. |
| `lint/src/rule/ts/interface_object_shape.rs` | A type alias that is an object shape | The two rulesets run it. Only an alias of a type literal is an error. A mapped type and an intersection are not errors. A test file is checked. |
